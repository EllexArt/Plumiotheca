# Revue tech lead — PR #98 (CI), PR #76 (architecture/backlog) et état de `main` — 2 octobre 2026

> Méthode : diffs complets des deux PR, tout le code de `main` (API, web, Docker, realm Keycloak), les 97 issues ouvertes. Build + tests API exécutés dans un worktree temporaire (4/4 passent). Preuve de concept (base PostgreSQL en mémoire `pg-mem`) confirmant les failles C1, C2, C4, C5 et C6 de `main`. Rien n'a été modifié.

## Verdict

- **PR #98 (CI, Dependabot, modèle de PR) : fusionnable après corrections mineures.** Workflows sains (pas de `pull_request_target`, jeton en lecture seule pour la CI, aucune entrée non fiable interpolée, CI verte), mais ils **publient en `latest`, sur un registre public, une image de l'API qui contient des failles critiques et tourne sur Node 20 (fin de vie le 30/04/2026)**.
- **PR #76 (architecture et backlog) : fusionnable après corrections mineures.** Document solide ; quatre contradictions internes (classement Explicite, avertissement « mineurs », thème sépia, « J'ai aimé ») et `backlog.md` déjà périmé. Les trous plus profonds (RGPD, images, file de tâches, ordre du backlog) peuvent passer en issues.
- **Code de `main` (hors PR) :** 5 failles critiques confirmées ; ne doit **en aucun cas être déployé**. La plupart sont couvertes par #9, #11, #12, #13, #14 ; le **vol de chapitre (C2)** et plusieurs points secondaires ne le sont pas.

## Points positifs

- Workflows sains, reproductibles, rapides.
- L'architecture corrige C1 à C11 dans son principe (contrats zod en liste blanche, sorties publiques, policies, migrations, JWKS).
- Choix adaptés à une petite équipe : application unique, contenu TipTap validé par schéma, révisions figées.
- Volet communauté rare et bien pensé (pas de messagerie privée, cercles sans discussions, décisions motivées avec appel).
- Les issues M1 (#11, #12, #14) reproduisent déjà les failles actuelles dans leurs critères.
